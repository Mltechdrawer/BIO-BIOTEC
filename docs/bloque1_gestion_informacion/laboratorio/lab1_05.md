# Práctica de Laboratorio 1.5. Mini flujo bioinformático reproducible

## Duración

**1 hora**

Esta sesión integra las cuatro anteriores y cierra la práctica de laboratorio del Bloque I.

---

## Objetivos

Al finalizar la sesión, el estudiante será capaz de:

- Resolver un pequeño problema bioinformático de principio a fin.
- Recuperar datos reales.
- Procesarlos mediante Python.
- Organizar datos, código y documentación.
- Registrar identificadores y versiones.
- Generar un resultado reproducible.
- Comprender el concepto de flujo de trabajo bioinformático.

---

# 1. El flujo de trabajo

Un análisis bioinformático puede representarse como:

**pregunta → datos → procesamiento → resultado → documentación**

En esta práctica se implementará una versión muy sencilla de ese ciclo.

---

# 2. Caso práctico

El profesorado asignará una entidad biológica.

El estudiante deberá:

1. localizarla en un recurso bioinformático;
2. verificar el registro;
3. descargar la secuencia;
4. procesarla;
5. generar un resumen;
6. documentar el procedimiento.

---

# 3. Paso 1. Pregunta

Formula una pregunta sencilla.

Ejemplo:

> ¿Cuál es la longitud y composición de la secuencia asignada y de qué recurso procede?


Registra:

```text

Identificador:
Organismo:
```

---

# 6. Paso 4. Resultado

Genera un fichero:

```text
resultado.txt
```

con una salida semejante a:

```text
Identificador: XXXXX
Organismo: XXXXX
Longitud: 1250
GC%: 47.8
Secuencia válida: Sí
```

---

# 7. Paso 5. Organización

Organiza el trabajo así:

```text
practica/
│
├── data/
│   └── sequence.fasta
│
├── src/
│   └── analysis.py
│
├── results/
│   └── result.txt
│
└── README.md
```

Esta estructura separa:

- datos;
- código;
- resultados;
- documentación.

---

# 8. Paso 6. README

El fichero `README.md` debe incluir:

## Objetivo

Qué se pretende analizar.

## Datos

- recurso;
- identificador;
- organismo;
- fecha;
- formato.

## Ejecución

Cómo ejecutar:

```bash
python analysis.py
```

## Resultado

Qué produce el programa.

## Limitaciones

Qué información no se ha analizado.

---

# 9. Reproducibilidad

Otra persona debería poder:

1. identificar los datos;
2. recuperar la misma secuencia;
3. ejecutar el código;
4. obtener el mismo resultado.

Para comprobarlo, intercambia el trabajo con otra persona.

La otra persona debe intentar seguir únicamente el `README.md`.

---

# 10. Actividad de revisión cruzada

Comprueba el trabajo de otro estudiante o pareja.

Responde:

- ¿puedo identificar el dato utilizado?
- ¿sé de dónde procede?
- ¿puedo ejecutar el script?
- ¿comprendo el resultado?
- ¿falta alguna información?
- ¿obtengo el mismo resultado?

---

# 11. Entregable

Entrega la carpeta completa con:

- datos;
- código;
- resultado;
- README.

Además, responde brevemente:

1. ¿Qué parte del flujo resultó más difícil?
2. ¿Qué elemento consideras imprescindible para que el trabajo sea reproducible?
3. ¿Qué cambiarías si tuvieras que analizar cientos de secuencias?
